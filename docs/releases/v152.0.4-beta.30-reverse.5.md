# Camoufox Reverse 152.0.4 beta.30 — reverse.5

This patch release keeps the 75-site PropertyTracer and protocol-v1 contract
from `reverse.4`, while making the two existing `localStorage` sites reachable
on Firefox 152's default storage implementation.

## LocalStorage correction

- Move `localStorage.getItem` and `localStorage.setItem` from the
  disabled-by-default, unsupported legacy `dom/storage/LocalStorage.cpp`
  implementation to Firefox LSNG's
  `dom/localstorage/LSObject.cpp`.
- Preserve the existing event object/property names, `call` kind, hook count
  (75), protocol (1), filters, and MCP aggregation behavior.
- The two optional native `site` values now name `LSObject.cpp`; consumers that
  persist exact site filters should update those two strings.
- Do not add the separate `PartitionedLocalStorage` branch in this patch. It
  remains an explicit future candidate that requires a third-party partitioned
  origin test before expanding the capability marker.

No MCP parser change is required. Use `camoufox-reverse-mcp` v1.4.0 or newer.

## Side-by-side installation

Keep the exact upstream beta.30 browser active, verify the downloaded SHA-256,
and use the installer attached to this release:

```bash
camoufox fetch official/prerelease/152.0.4-beta.30
camoufox set official/prerelease/152.0.4-beta.30
python3 install-camoufox-reverse.py camoufox-152.0.4-beta.30-<platform>.zip \
  --sha256 <value-from-SHA256SUMS>
```

Then select only this MCP launch:

```text
launch_browser(
  browser_version="whitenightshadow/152.0.4-beta.30-reverse.5",
  enable_trace=True
)
```

The installer does not change the active browser or migrate a legacy 0.4
cache. Existing reverse builds remain installed side by side.

## Validation gates

- Fail-closed injector tests confirm exactly 75 unique sites and require both
  `localStorage` hooks to target `LSObject.cpp`, with no legacy path remaining.
- A real HTTP-origin browser smoke must observe native `localStorage` and
  `sessionStorage` get/set events in raw JSONL and MCP summary output.
- Trace-off, native acknowledgements, get/set/call classification, filters,
  event caps, multiple sessions, private-run isolation, and cleanup regressions
  remain covered.
- Linux x86_64, Windows x86_64, macOS x86_64, and macOS arm64 packages are
  built from one tagged input and verified by release hashes and manifest.

Tracing remains opt-in. A hit is strong evidence within the fixed native
coverage set; a miss is not proof that an unhooked JavaScript property was not
used.
