# Camoufox Reverse 152.0.4 beta.30 — reverse.4

This is the production PropertyTracer release for the Firefox 152 line. It
keeps the same 75 native Gecko DOM/Web API injection sites and protocol-v1 core
fields as Firefox 135 and `reverse.3`, while improving correctness, ordering,
performance, and multi-session reliability.

## PropertyTracer improvements

- Preserve the existing JSONL fields `o/p/v/t/k` and `on`/`off` control
  protocol for older consumers.
- Correctly classify native events as `get`, `set`, or `call`; previous builds
  reported all 75 sites as `get`.
- Add backward-compatible event extensions:
  - `s`: stable native injection site;
  - `q`: per-process/session sequence;
  - `u`: relative microseconds;
  - `w`: Unix epoch microseconds for deterministic cross-process merges.
- Restore bounded asynchronous batching. Disabled tracing remains one atomic
  branch; enabled tracing no longer performs one synchronous disk write per
  property access.
- Drain in-flight buffers before closing a session, serialize flush/close, and
  handle interrupted or partial writes.
- Create trace files with `O_EXCL` and private `0600` permissions instead of
  appending to a path left by a reused PID.
- Add per-process on/off acknowledgements and a run-level desired state so
  content processes created during a transition cannot reopen a stopped trace.
- Use native filesystem paths on Windows so non-ASCII user/cache directories
  can create control, status, and trace files reliably.
- Initialize the tracer only in Firefox parent and page-content processes;
  Socket/GPU/RDD utility processes do not expose page DOM and no longer create
  controls they cannot service after sandboxing.
- Stop doing per-event work after the configured session cap is reached.

The capability remains a fixed native coverage set, not arbitrary JavaScript
object-property tracing. A recorded hit is strong evidence; a missing event is
not proof that a property outside the 75 sites was unused. The tracer does not
modify page JavaScript objects, descriptors, or prototypes, but very high event
rates may still be observable through timing.

## MCP pairing

Use `camoufox-reverse-mcp` v1.4.0. It assigns each browser launch a private
trace directory, validates live control PIDs, supports interactive
`start -> page actions -> stop`, and preserves existing blocking capture calls.

```text
launch_browser(
  browser_version="whitenightshadow/152.0.4-beta.30-reverse.4",
  enable_trace=True
)
trace_property_access(action="start")
# perform page actions
trace_property_access(action="stop", mode="summary")
```

Tracing is still disabled by default. Enabling it temporarily disables the
Firefox content sandbox so content processes can write the private trace run;
normal browser launches keep the upstream sandbox and behavior.

## Side-by-side installation

Keep the exact upstream beta.30 browser active, then use the release installer:

```bash
camoufox fetch official/prerelease/152.0.4-beta.30
camoufox set official/prerelease/152.0.4-beta.30
python3 install-camoufox-reverse.py camoufox-152.0.4-beta.30-<platform>.zip \
  --sha256 <value-from-SHA256SUMS>
```

The installer places the build in
`browsers/whitenightshadow/152.0.4-beta.30-reverse.4/` and does not change the
active browser. Existing 135, reverse.2, and reverse.3 installations remain
untouched.

## Validation gates

- Native C++ concurrency/control smoke tests and the fail-closed 75-site
  injector suite.
- Linux x86_64, Windows x86_64, macOS x86_64, and macOS arm64 packages built
  from one tagged input and verified against the release capability marker.
- Real Linux and local macOS arm64 browser launches with tracing off/on,
  get/set/call events, cross-process ordering fields, multiple sessions, and
  buffer drain checks.
- MCP v1.4.0 unit suite, concurrent-run isolation, stale-control rejection, and
  official-browser no-trace regression.

Mozilla's central WebIDL tracing entry was evaluated as a future opt-in broad
scope. It is intentionally not enabled in this release because the fixed 75-site
profile has a much smaller compatibility and logging surface. Firefox's full
ExecutionTracer is also not used.
